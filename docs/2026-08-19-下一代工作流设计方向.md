# Dev Flow 下一代设计方向（2026-08-19，拷问定稿）

- **状态**：方向合同。经一轮 grilling 拷问修正定稿（12 项共识 + 2 项裁决，见附录）。本文只锁定方向与原则，不涉及实现方案；实现设计不得违反本文原则，如需违反，先改本文并说明理由。
- **已拍板的决策**：① 做减法、彻底重写，不在 6.0 基础上缝补；② 先只适配 Claude Code，Codex / Kimi Code 后续通过宿主事件抽象扩展；③ 吸收旧版有用资产（思想、判断标准、测试知识、基建），不带旧代码与历史负担；④ 重写在新分支进行。

## 1. 为什么推倒重写（诊断结论）

### 1.1 历史事实

对 139 个提交（2026-07-05 → 08-18）与五份问题清单（8-12 → 8-18）的复盘：

- 提交分布 feat 44% / docs 25% / fix 12% / **refactor 1%**——一直在加功能和补漏，几乎不做结构整理。
- 修复主题高度集中：版本号同步 10+ 次；review 审查门禁 4 次逐层打补丁；trace/回滚登记校验 4 次（全是"规则存在但某分支漏执行"）；hook 写入门禁 3 次（每个路由分支单独补）。
- 16 天内 5 个大版本（2.0→6.0），每次都是"删旧合同 + schema 硬切换"。rollback-units 5.0 引入、6.0 删除——设计决策频繁逆转。
- 问题清单层面：同一问题（子代理评审派发）8-15 标记修复，8-18 原样再现。"修一轮、真机再爆一轮"。
- 代码现状：4 个巨型文件占 core 近 1/4 行数；v6 声称硬切换但 v5 残留代码与测试仍在；`tests/legacy-v1/` 45 个测试无人运行。

### 1.2 根因四条

1. **流程靠模型自觉调用工具驱动**。约 40 个 MCP 工具要按正确顺序调用，协议横跨 MCP 工具、skills 文档、hooks、子代理四层。模型忘调、顺序错、任何一层脱节 → 流程卡死。
2. **声明前置的分类与锁定**。开局问卷式分类本身就是仪式；分类锁错则全程错；做到一半发现判错要走 reclassify 仪式纠正。
3. **fail-closed 但不 fail-visible**。被拦后不知道卡在哪、该干什么，只能盲目重试。
4. **开发反馈环过长**。改代码 → 发版 → 其他项目安装更新 → 才能验证，每轮迭代都要付这个税。

### 1.3 结论

四个根因都在驱动模型与判定模型上，属于架构层。在旧架构上继续修补，等于给第七次大版本硬切换攒素材。**重写的目标不是换一批抽象，而是换掉驱动模型。**

## 3. 范式与北极星

### 3.1 作废"自觉 vs 强制"这根轴

现有工作流框架都在同一根轴上选位置：Superpowers / Matt Pocock Skills 押模型自觉（提示词、技能触发词），摩擦低但失守概率高；Spec Kit / OpenSpec 押规范产物；旧 Dev Flow 押机器强制，失守概率最低，但强制的实现方式是"模型当司机、工具当方向盘"——这正是死循环的根。

新方向不是在轴上挪位置，而是作废这根轴：

> **流程由宿主事件驱动，不由模型驱动。** 写文件、改代码、提交、会话结束，这些动作本来就会自然发生；流程状态在事件流上自动推进，门禁在事件流上自动拦截。模型从头到尾不需要"记得走流程"，甚至不需要知道流程存在。

精确化一句：强制只能发生在**事件边界**（写入前、命令后、会话开始等宿主事件点），模型在事件之间的思考无法也不需被强制。新范式让每个事件边界上的"正确选择"成为唯一可行选择，而非靠模型自觉。

旧版被证明正确、必须继承的核心判断是：**执行正确性不能押在模型自觉上**。要改变的是强制的着力点：从"模型必须主动调对工具"换成"事件流上的被动拦截与推进"。

### 3.2 北极星

> **让正确的流程在自然开发中自动发生——零仪式、零自觉、可证明。**

"可证明"的意思是：领先与否不靠文档自述，靠对标基准数据（见第 8 章）。任何一段设计如果只能说"这样更先进"而说不出"这样让哪个真实场景的哪个指标变好"，就是口号，删掉。

## 4. 设计宪法（六条）

### 4.1 隐形治理

流程是基础设施，不是用户界面。小任务的理想体验：用户和模型都感觉不到流程存在，事后发现该拦的都拦住了、该记的都记下了。**任何"为了走流程而走流程"的交互都是 bug，不是功能。**

### 4.2 方向债前置，规模债后置

**方向债（动手前想没想对）——必须前置，零问卷。** 大任务最贵的错误是方向错误，行为证据对它天然滞后。动手前的信号源有两个：用户的那句话（"重构鉴权模块"与"改个文案"天差地别）和模型的探索轨迹。落点是**首写入门禁**：流程起点零提问直接放行；第一个实际写入动作触发一次方向判断，需要先对齐的拦在这一刻给计划摘要确认（一次，不是问卷）；判定为小任务的瞬间通过。方向对齐发生在"第一行代码写入前"这个最便宜的纠错时刻。（机制细化见 6.1）

**规模债（需要多重的工序）——后置跟随行为。** 审查、追溯、集成验证等义务按**实际写入行为**渐进加码，只升不降。判定信号只用写入行为（改了几个文件、跨了几个模块、碰没碰敏感路径）——探索轨迹与任务规模不相关（小而陌生的 bug 要读 30 个文件，熟悉的大重构读 5 个就动手），**探索轨迹降级为线索，只在首写入门禁用一次，不参与治理分级**。

**大任务晚拦截的四道防线**（针对规模债）：① 升级点在第一次越界写入的瞬间，不是交付时算总账；② 敏感路径天然是信号，不参与默认最轻，第一次触碰即升级；③ 不可逆操作（git push、删表、发版）永远有人工门禁，与任务大小无关；④ finalize 审计兜底，交付时对比实际变更面与经历的治理，不一致显式警告，不阻塞但事后一定可见。

### 4.3 删除是一等功能

- 状态契约 additive-only：字段只增（带默认值），禁止改名/删字段/改类型。**生效时点为契约冷冻点 = 第一个稳定版 1.0.0**，判据客观：基准全绿 + ≥5 个真实任务（含 1 个 M 级行为特征）走完无契约级问题。冷冻点前（0.x）契约自由改、不承诺兼容。
- 复杂度预算机器校验：工具数、错误码数、模块数设预算上限，超限必须显式说明删除了什么。
- 新增必答三问：现有机制能否吸收？删了什么来换？预算还够吗？
- 重写本身是该原则的第一次实践：rollback 事务系统让位 git、开局分类让位行为判定、约 40 个工具面推倒。

### 4.4 流程要像好同事，不像安检门

主路径顺不算本事，脏路径不烦人才是。真实开发是混乱的：用户随时打断、改主意、自己动手；模型会卡、会误判。五条脏路径准则见第 5 章。

### 4.5 防循环三纪律（一切机制的合法性检查）

死循环的病因不是审查层数，是单个机制违反三纪律之一：**① 无主动登记负担**（信息自动收集或自然输出，不存在"漏登记被拦"）；**② 阻断必 fail-visible**（说清现状、缺什么、怎么解）；**③ 人有一句话终裁权**（出口不经过流程，对话里说句话即解锁/豁免）。违反任何一条的机制，不管多有价值，不准进。层数不是变量，三纪律才是。

### 4.6 故障分级（治理系统自身不成为新阻塞）

- **系统故障**（hook 崩溃、状态损坏）：一律 **fail-open**——放行 + 显眼警告 + 审计可见；**只报警不自修复**（读取失败 ≠ 损坏，自动修复比故障危险；重建只在 doctor 命令手动触发，且先备份）。门卫晕倒不该把楼锁了。
- **判定错误**（归属串线、敏感路径漏判、误锁）：不是故障，靠代价分级——提示级 > 审计级 > 锁定级，让误判成本趋零。
- **锁定的着力点是"完成宣称"这个必经咽喉，不是文件写入**（锁文件可被换文件绕过；锁定期间可改任何文件，唯独完成宣称不被接受——绕过没有意义）。
- **解锁是信息注入，不是机械重置**：用户解锁时给的上下文（"环境有问题"/"验收标准错了"）必须改变后续计数语义。

## 5. 真实开发场景的解决方向

每个场景三栏：真实场景 → 旧版死因 → 新版对策。这些准则优先级高于主路径的任何设计。

### 5.1 中途插入无关修改

- **场景**：做到一半，用户说"等下我先改下 config"或"顺手把 README 的 typo 改了"。
- **旧版死因**：fileScope 校验拦范围外写入 → scope drift 交互问"纳入还是排除"；手动改的文件污染 ownership，回头要调工具对账。
- **新版对策**：**选择性失明**。流程管辖边界只覆盖主线任务相关文件与高风险路径；无关、低危改动不触发任何流程逻辑，静默记账。防作弊（拆大任务绕过治理）不靠拦截旁路，靠 finalize 审计事后可见。**防作弊的成本不该让正常用户付。**
- **准则**：流程只管主线，旁路自由。

### 5.2 中途需求变更

- **场景**：代码写一半，用户说"我想了下，标签还应该支持颜色"。
- **旧版死因**：revise_decision 登记 → revise_plan 修订 → 可能 reclassify，一轮修订仪式。
- **新版对策**：需求变更是常态输入，不是异常。**按影响分级吸收**：增量变更静默吸收进需求记录，模型回一句"收到"就继续；推翻已完成工作的变更才停下一次，说清"已写的 X 作废、Y 要改"，用户确认后继续。**变更处理的重量与变更影响成正比。**
- **准则**：需求是活文档，收敛靠演进不靠锁定。（形状见 6.5）

### 5.3 验证连续失败（卡点）

- **场景**：验收不通过，改，还不通过，第三次了。
- **旧版死因**：每次失败一个错误码，fail-closed 但不 fail-visible，盲目重试——"卡住且不可见"死循环主产地。
- **新版对策**：**连败计数 + 锁定求助**。关键定义：**TDD 开发循环里的红灯永远不计数**（红→绿是节奏不是失败）；计数只挂在"**宣称完成被验收驳回**"上——"我以为完了但事实不同意"才是卡点信号，它暴露的是自我评估失真。连续 3 次驳回 → 锁定完成宣称（不是锁文件），唯一出口是用户下一轮输入（解锁即信息注入，见 4.6）。求助呈现必须区分**实现错了还是验证本身错了**（测试写错、环境坏了）。
- **准则**：卡住不可怕，可怕的是卡住没有出口。出口不是重试，是带着上下文来找人。

### 5.4 用户直接改了文件，模型不知道

- **旧版死因**：workspace-ownership 交互 + 手动 reconcile 工具，重且烦。
- **新版对策**：**文件系统是唯一事实源**，不是状态文件。会话恢复或继续时先静默读取真实状态：用户改了，吸收进去，不打断；改动与主线冲突时才说一句话。
- **准则**：静默对账，冲突才说话。

### 5.5 紧急修改（逃生门）

- **场景**：半夜线上出 bug，急着改一行。
- **新版对策**：**逃生门**——用户说"急，直接改"，放行，记账，事后审计可见。治理的价值在于不挡该走的路。
- **准则**：信任但记账，不是怀疑且拦路。

### 5.6 会话中断与恢复

- **新版对策**：SessionStart 时自动恢复并主动播报："你昨天在做标签功能，做到验证阶段，还差 X"。配合 5.4 静默对账，恢复零操作、零提问。
- **准则**：恢复是流程的义务，不是用户的记忆负担。

### 5.7 两条主线（软单主线）

- **场景**：做标签功能时用户说"另外把登录那个 bug 也修了"——第二条正经主线。
- **新版对策**：**同时只有一条主线接受治理**；用户说"先弄那个"，当前主线自动挂起（状态保留），新的成为活跃主线；恢复走 5.6。写入归属因此永远明确：归活跃主线。不做完全并行多主线——归属歧义会毒化行为判定。归属串线时纠正零仪式（"刚才那几个文件算另一条线"，一句话重新归集），且归属错误后果是提示级/审计级，不是锁定级（4.6）。
- **准则**：用户可随意多线跳，流程一次只专注一条线。

## 6. 核心机制定义

### 6.1 意图块（首写入门禁的双层结构）

hook 是脚本进程，做不了"重构鉴权 vs 改文案"的语义判断，所以拆两层：

- **引导层**：模型首次写入前输出 2-3 行意图块——做什么、预计动哪些文件、有没有敏感路径/风险标签。语义判断交给最擅长的两方：模型生成，用户扫一眼（不打断、不需要回答，觉得不对随时自然语言叫停）。大任务的意图块扩展为**计划摘要，按需求编号逐条组织**（哪个步骤覆盖哪条需求一目了然）。
- **强制层**：hook 只做规则能做的硬校验——意图块存在吗？写的是敏感路径吗、声明了吗？不存在或未声明就拦，报错附模板。

### 6.2 治理判定

- 信号 = 实际写入行为（文件数、跨模块、敏感路径），不用探索轨迹（4.2）。
- 风险标签（security/data/money/external/availability/critical_correctness/irreversible）**正交于规模**：敏感路径表机器判一部分；语义风险（如外部 API 变更）由模型在意图块自报、用户扫读核对、finalize 审计校验声明与改动是否相符。改一行支付逻辑规模是 XS，风险是 money——规模定流程重量，风险定义务种类。
- 治理强度跟随行为只升不降；XS/S/M/L 保留为度量词汇（仪式预算、基准报告），不再是身份标签，**没有分类动作、没有锁定、没有固定路线**。

### 6.3 完成宣称（done）

三通道并列，任一触发即完成，幂等（重复触发无副作用）：

1. **模型通道**：唯一保留的工具 `done`，前置硬校验"最近一次验收命令通过"——未通过则驳回，连败计数 +1（5.3 的技术实现）；
2. **用户通道**：对话里说"好了/完成了"，宿主事件识别；触发前展示当前待完成阶段摘要让用户确认一次（防"这步完成了"被误判为全完成）；
3. **兜底通道**：都忘了，下次会话恢复时静默对账发现"验收已过、只差关闭"，一句话确认收尾。

三条通道合起来，完成宣称不存在"没人触发"的死局。**"用户已确认"的声称必须由宿主事件证明，模型自述无效**（attestation 原则，旧版 8-15 P0-2/P0-3 流血换来的知识）。

### 6.4 评审（极简重做）

- **三级触发**：XS 行为特征不评审；行为升级后交付前必经一次；敏感路径不问规模必审。用户随时可手动加严（"这个给我审一遍"，一句话生效）。
- **执行**：原生 Task 子代理 + SubagentStop hook 把关。结论结构化，**blocking 必须具体**（文件+行+理由，模糊意见无权拦）；复审只审 blocking 项，不全面重审；用户有一票终裁权（"这个问题接受，放行"）。评审-修复 N 轮不收敛，套 5.3 连败锁定。
- **审查清单（双轴 + 回撤视角）**：需求轴（需求条目+计划摘要+实际改动三件套对齐，真实性判断）、规范轴（仓库规范与约定遵守）、大任务加回撤可操作性视角（"怎么证明能安全撤回"作为审查项，不是独立机制）。
- **真实性硬约束**（旧版流血知识）：评审必须独立子代理上下文（防自审自）；评审结论与代码内容 sha 绑定，代码变结论失效（防拿旧评审冒充）；评审输入基于不可变快照（防上下文污染）。
- **角色按风险事实派生**：碰支付路径自动加 money-safety 视角，碰密钥目录加 security 视角。
- **对抗定位明文**：评审的职责是找茬，不是走过场。

### 6.5 需求活文档

- 形状：状态文件里的条目列表，每条 = {编号、内容、来源（用户原话/仓库事实/意图块推断）、时间}。**没有状态机、没有确认字段、不落 Markdown**（WHAT 层是 OpenSpec/Spec Kit 的战场）。
- "确认"不是字段，是用户在交付对照表上扫一眼那个动作本身。
- 旧版 Decision Ledger 并入条目的来源字段（带"决策"标记），不单独一套。
- 提问质量合同（旧版 grillme 的灵魂保留）：非问不可的问题必须带事实、冲突、选项（A/B/C）和推荐，能用工具查明的绝不问人；**推荐选项必须附"不选它的最强理由"（反向论证）**，防模型用 framing 引导用户点头。

### 6.6 自动证据链

追溯从"模型手工登记的图"降级为**零操作证据链**：需求条目 → 意图块 → 文件改动清单 → 自动 git commit（阶段检查点）→ 验收结果，全部由 hook 自动归集。放弃图完整性校验（历史修 4 次全是登记遗漏）。对竞品的差异化表述从"可审计追溯图"改为"**零操作证据链**"——每个改动自动讲清来历。将来真需要图，按 4.3 加法再加。

## 7. 能力砍留（存在形态）

| 能力 | 结论 | 新形态 |
| --- | --- | --- |
| write-gate 写入门禁 | **保留，升级为骨架** | 事件流统一拦截点；拒绝必 fail-visible |
| review 评审 | **保留，极简重做** | 见 6.4；批次/终态/豁免状态机砍掉 |
| grill 需求澄清 | **保留，零提问默认** | 原生问答一次问完一轮封顶 + 提问质量合同（6.5） |
| trace 追溯 | **砍重做** | 自动证据链（6.6），无图校验无登记工具 |
| rollback/checkpoint | **砍，让位 git** | 阶段自动 commit 即检查点，撤销交原生 git；回撤可操作性降为评审视角（6.4） |
| 路线分类 classify/lock/reclassify | **砍** | 治理级别由行为推导（6.2），无分类动作 |
| pause/resume/reconcile | **砍工具，改自动** | 会话事件自动恢复与对账（5.4/5.6） |
| git 写门禁 | **转向** | commit 从被拦对象变为流程自身的检查点载体；只拦 push 等不可逆操作（4.2 防线③） |
| MCP 工具面 | **约 40 → 个位数** | 流程推进全靠事件驱动；`done`（6.3）+ 只读查询类 |

## 8. 测量与验证（怎么证明，而不是口号）

### 8.1 对标基准（推迟启动）

**裁决：竞品基准推迟到新方案跑通之后**。启动后形态：从真实需求里选任务包（含脏路径变体），与 Spec Kit / OpenSpec / Superpowers 同场人工执行，**按时间、交互摩擦、token 消耗等多维度对比**；任务包、记录方法、原始日志全部入库可复核；指标只用场景语言（"用户中途改需求后几轮交互回到正轨"），不用机制术语；里程碑节奏执行，记录竞品版本号。

### 8.2 仪式预算（ceremony budget）

目标线写入合同：XS 级行为特征任务 ≤ 2 次用户交互；每版本对比"变轻了还是变重了"，超线在交付报告显式提示。

### 8.3 性能预算（生死线，不是优化项）

hook 密度新版更高，hook 慢 100ms 用户就能感知卡顿——隐形治理会变成可见摩擦。**P95 单事件耗时目标写入第一批验收标准**（参考旧版 1.3 的 <20ms 目标，实测后定），含只读缓存、token 面收敛（响应不返回全量状态）。

### 8.4 开发反馈环（自身工程）

- Claude Code 本地插件目录加载 + watch 构建 + sandbox 验证项目：改完源码秒级真机验证，**不发版**；
- 一键真机冒烟扩展现有 e2e 基建；
- 版本号单一来源，发布一条命令 + CI 校验（修复历史 10+ 次版本同步事故）。

### 8.5 测量仪先于干预上线

行为判定阈值（几次连败触发锁定、什么算越界）必须用真实数据校准，不拍脑袋；误判多的自动升级本身就是新摩擦。

## 9. 边界（明确不做）

- 不做规范文件管理（WHAT 层）——不发明新文档格式；
- 不做 dashboard / 营销面；
- 不做多任务并行——软单主线（5.7），旁路自由（5.1）；
- 不做回滚事务系统——git 检查点 + 评审回撤视角；
- 不强制 TDD——验收必须有通过的验证命令（6.3），但 TDD 流程不强制（XS 任务全套测试成本可能高于收益）；
- 多宿主推迟——宿主事件从第一天就是薄抽象层，扩展 Codex / Kimi 时不推翻核心。

## 10. 风险与诚实账

1. **宿主事件能力边界**：hooks 能拦多少、拦后能否给出足够 fail-visible 信息，由 spike 验证（第 12 章）。验证不足的强制点回升为个位数 MCP 工具兜底——预案不是失败。
2. **行为判定误判成本**：自动升级误报多即新摩擦。对策：8.5 测量先行，阈值数据驱动。
3. **敏感路径覆盖度残余风险**：内置规则必然漏项目自定义路径。缓解：项目配置补充 + finalize 审计启发式报警。**承认不归零**——任何规则系统都有此风险。
4. **蓄意绕过防不住**：锁定防的是无意识空转；模型有意识地对抗流程，任何系统都防不住——防线在评审独立性、交付审计与用户终裁，不在锁。
5. **方向债不可免疫**：首写入门禁只能在最便宜的暴露时刻拦，不能保证方向永远对；走错时细粒度检查点降损失，但不消除。不吹"防错"。
6. **重写丢失边界修复知识**：139 个提交里大量 fix 是真实场景踩出来的。对策：旧 107 个单元测试作为"坑清单"逐条核对新实现覆盖。
7. **再犯历史病**：本项目的历史模式是"遇到问题开大版本推倒"。防复发机制即 4.3——冷冻点后只能删着改，不能推倒改。

## 11. 旧版资产吸收（三层模型 + 融洽三检验）

| 层 | 内容 | 吸收方式 |
| --- | --- | --- |
| **原则层** | 强制不靠自觉；查明优先；风险正交于规模；删除一等；fail-visible；真实性证明（确认须宿主事件、评审独立且绑代码） | 进宪法与机制硬约束，一字不改 |
| **判断标准层** | 什么算完成（验收通过）、什么算对齐（三件套）、评审审什么（双轴+回撤）、提问什么标准（事实+选项+推荐） | 进已有机制内部的检查清单，**不设独立环节** |
| **机制层** | 40 工具、状态机、批次生命周期、回滚事务系统 | **不吸收**，全部在新范式里重写 |
| **知识层** | 139 提交 fix、五份问题清单、ADR 0019-0026、107 个测试 | 进"坑清单"，新实现逐条核对 |

**每条吸收必须连过三关，否则拒收**（防补丁回流的闸）：① 附着点检验——能附着在新版哪个已有机制上？附着不上 = 新环节 = 默认拒绝；② 三纪律检验（4.5）；③ 痛点检验——服务第 2 章四个痛点里的哪一个？答不上 = 口号，删掉。

已过三关的吸收清单：真实性证明（→ 附着 done 与评审）、风险标签（→ 附着意图块与审计）、git 门禁转向（→ 附着检查点）、policy 纯函数 + 组合性质测试（→ 附着开发纪律）、性能预算（→ 附着第一批验收标准）、状态落业务仓 `.dev-flow/`（→ 附着存储设计）。

## 12. 落地节奏

**第 0 步：spike（一周，出结论前不写正式代码）**。验证四个宿主事件能力：PreToolUse 能否拦写入并返回结构化错误；SessionStart 能否注入状态；完成确认能否被事件识别；SubagentStop 能否拿到子代理结论。失败项回退 MCP 工具兜底。

**第一批（MVP）**：状态记账 + PreToolUse 写门禁（fail-visible）+ 敏感路径硬门禁 + SessionStart 恢复 + done 三通道 + 逃生门 + 证据链原始记录。
**北极星**：XS 任务零仪式走完，越界（含敏感路径）可见可拦。
**判据**：连续 5 个真实 XS 任务，交互 ≤ 1 次/任务、零卡点、证据链完整。MVP 期大任务的非敏感部分无升级评审——这是明示的已知边界，靠证据链数据 + 用户自知兜着，不是禁令。

**第二批**：行为升级判定、评审重做（6.4）、连败锁定（5.3）、证据链渲染与交付对照表。

**第三批**：契约冷冻（4.3 判据）、竞品基准（8.1）、多宿主抽象验证。
