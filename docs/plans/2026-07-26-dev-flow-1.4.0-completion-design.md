# Dev Flow 1.4.0 补漏设计

> **状态：** 已确认，待实施  
> **日期：** 2026-07-26  
> **范围：** 补齐 1.4.0 实施文档与现有未提交实现之间的确定性缺口；不伪造人工回放结果。

## 目标

使 1.4.0 的可发现性、artifact 写入流程、静态约束和自动化回归测试与实施文档一致，并让发布验证命令可在原生 Windows shell 中执行。

## 方案

1. **Artifact UX**：所有会修改路线 artifact 的 Skill 都明确执行
   `scaffold → Read 已登记路径 → Edit/Write → record_artifact`。MCP scaffold tool description 同步说明这个后续顺序；静态测试逐个覆盖 artifact owner。
2. **Evidence / freshness 测试**：增加 nextAction、MCP `dev_flow_next`、status 三个响应面的 requiredEvidence 矩阵；补齐 verification missing/fresh/stale 与 protected-root stale 时 feature-check/finalize 拒绝的回归测试。
3. **契约与文档**：README 只链接 contract/MCP schema，不再手写风险标签；非法 risk label 的恢复提示严格采用实施文档文本。
4. **跨平台卫生**：移除孤立 CR，新增 `.gitattributes` 固定文本为 LF；用本地 Node 包装器设置 `HOST_E2E`，避免依赖 POSIX 的环境变量前缀。
5. **发布证据**：新增双宿主真实回放记录模板，列出 5 项必须回放及宿主/Node/输入/输出记录字段。模板默认未通过；真实 Claude、Codex 与浏览器/用户签收只能由实际执行者填写。

## 非目标

- 不增 route、gate、MCP tool、FeatureState 顶层字段或 schema migration。
- 不把脚本测试或 token 测试描述为真实 Agent / 浏览器回放。
- 不改变现有 risk policy 和已实现的 evidence enforcement 语义。

## 验收

- `git diff --check` 无输出。
- `npm test`、`npm run build:check`、`npm run test:host-e2e` 通过。
- 新增测试分别验证 core、MCP、status 的 enriched action 及 freshness 三态。
- 回放模板存在但所有未执行场景仍标为 pending。
