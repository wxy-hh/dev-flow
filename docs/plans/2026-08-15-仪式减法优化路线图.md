# Dev Flow 仪式减法优化路线图（2026-08-15）

- **定位**：过程计划（非合同）。记录从当前架构审查轮收尾到「仪式成本与治理价值再平衡」的完整路径，按依赖关系排序。
- **前置条件**：`docs/2026-08-13-架构审查报告.md` 的 9 个候选全部完成（当前工作区 80 文件、净删约 5250 行，测试全绿但未提交）。
- **三个初衷**（排序与取舍的唯一判据）：
  1. 小任务不过度治理；
  2. 高风险任务不能轻易越级；
  3. 规则长期维护而不持续膨胀。

## 排序原则

1. **测量先行**：所有行为干预之前，先有测量仪（ceremony budget、surface-check），否则干预效果无法归因；
2. **风险分层**：零风险（测量/纪律）→ 低风险（策略调整）→ 中风险（interface 变更）→ 高风险（动核心不变量），逐层推进；
3. **干预独立成版**：每次行为干预单独发版、单独验证，一次只改变一个变量；
4. **数据驱动升级**：只有低风险方案被数据证明不足时，才升级到高风险方案（如 quick lock → provisional）。

## 阶段 0：基线锁定（当前轮收尾）

**0.1 收尾架构审查轮并发版**

- 内容：当前 9 候选全量测试通过后提交（中文 Conventional Commit）→ `version:sync` → `build` → 发版。
- 前置：无。
- 理由：80 文件未提交的基线不能继续漂移；所有后续工作必须站在干净基线上。
- 完成标准：`npm test` 全绿 + 版本号落盘 + dist 同步。

## 阶段 1：测量与纪律（零/低风险，发版后立即）

### 1.1 ceremony budget 埋点（治理成本度量）

- 风险：**零**（纯测量，不改任何行为）。
- 内容：status 投影与最终报告增加「本次任务：工具调用 N 次、用户交互 M 次、证据 K 件」；目标线写入 contract（XS ≤ 2 交互 / ≤ 10 调用；L ≤ 8 交互 / ≤ 40 调用），超线在 finalize 报告显式提示。
- 前置：0.1。
- 为什么最先：它是后续所有干预（3.x/6.2）的**测量仪**；没有它，真实项目验证只有"感觉"没有"数据"。
- 验证：单测覆盖统计字段；真实任务观察输出。

### 1.2 surface-check 复杂度预算（CI 门禁）

- 风险：**零**（纯测量 + 断言）。
- 内容：`scripts/surface-check.mjs` 纳入 `npm run build:check`：公共工具 ≤ 50、错误码 ≤ 35 族、core 模块 ≤ 70、交互类型 ≤ 5 族。先立基线，超限必须显式更新预算并说明删除项。
- 前置：0.1；与 1.1 独立可并行。
- 为什么：这是"规则不膨胀"从愿望变成机器可验证事实的唯一手段。

### 1.3 hook 性能（工程债）

- 风险：低（行为不变）。
- 内容：六事件每次 spawn Node 进程的开销——状态读取按 revision/mtime 缓存、健康信号 15 分钟窗口内内存缓存不重复写盘、事件账本批量写。
- 前置：0.1。
- 理由：这是"理念一流、工程化不足"最直接的体感证据；每次工具调用几十 ms 的 hook 开销是真实摩擦。

### 1.4 token 面收敛

- 风险：低。
- 内容：mutation 响应统一走 compact 投影（`server.ts` 已有 `compactMutationResult`），事实登记等路径不再返回全量 FeatureState；配合 8-13 清单第 6 条的批量登记落地。
- 前置：0.1（8-13 清单第 6 条已在当前轮或随其后完成）。

### 1.5 纪律条款（additive-only schema + 减法变更协议）

- 风险：零（文档纪律）。
- 内容：写入 CLAUDE.md/AGENTS.md——
  - FeatureState 字段只允许新增（带默认值），禁止改名/删字段/改类型，永不做 v6 迁移器；
  - 新增任何控制/工具/错误码/交互前必须回答三问：①现有机制能否吸收？②删除了什么来换？③复杂度预算是否还够。
- 前置：无。
- 理由：任何系统都会在迭代中膨胀，除非"删除"被做成强制流程。

## 阶段 2：真实项目验证（有界实验，只记录不优化）

**2.1 三任务验证 + 发现三分法**

- 内容：带 1.1 埋点跑 3 个真实任务（2 个 XS/S + 1 个 M），采集调用数/交互数/卡点轮次（翻源码、重复 doctor、重试循环均记录）。
- 前置：1.1（必须有数据采集器）；时间盒一周。
- 发现处置三分法：
  | 类型 | 判定 | 处理 |
  | --- | --- | --- |
  | 当前轮回归 | 之前能走通的行为变了 | **立即修**（bug-fix 批，单独提交），修完重跑确认 |
  | 独立缺陷 | 与当前轮和计划干预都无关 | 小则修，大则登记 `.scratch/` 排期 |
  | 干预目标 | 正是 3.x/4.x/6.2 要消灭的摩擦 | **登记不修**，留给对应干预，避免重复劳动 |
- 完成标准：回归清零、基线数据落盘（作为所有干预的"before"）。

## 阶段 3：低风险干预批（数据支持的第一个干预，单独成版）

### 3.1 boundaryAudit XS/S 默认处置

- 风险：低（策略调整，纯 policy 函数 + 一个交互）。
- 内容：`assertBoundaryAuditComplete`（route.ts:374）对 XS/S 允许 `scanned: [六类], items: []` + 一次"确认无未处置边界"（绑定 search-absent 事实或并入 route-confirmation）；M/L 保持逐项。
- 前置：2.1（数据确认 XS/S 前置摩擦确实存在）；**先于 3.2**（先定审计形态，再动锁定流程）。
- 验证：单测 + 1 个真实 XS 任务，对比 2.1 的 before 数据。

### 3.2 quick lock（lazy lock 第一步：快速锁定）

- 风险：低-中（保留"lock 前置"不变量，只降输入负担）。
- 内容：XS lock 输入降到最低（3 个 signals + 无风险声明 + 一次确认），**不动** write-gate 写 seam、不引入 provisional 状态机。
- 前置：3.1（建立在新审计形态上）。
- 验证：真实 XS 任务对比 2.1 数据；确认越级防线行为不变（回归测试锁定 `assertTopologyLevel`、`RECLASSIFICATION_DOWNGRADE_FORBIDDEN` 路径）。

### 3.3 scope drift 检测（行为级越级检测）

- 风险：低。
- 内容：implementation 中模型第一次写到 `scope.inScope` 之外的文件时触发一次范围漂移交互：纳入（→ 重新分类，只允许向上）或排除。write-gate 已有路径，加比对即可。
- 前置：2.1；与 3.1/3.2 独立（无依赖），可与批 3 同版或单独。
- 理由：这是唯一基于**实际行为**的防越级防线（XS/S 无 unit-chain 时），比声明检查强一个量级。

## 阶段 4：防越级加固（策略层，低成本）

### 4.1 信号-事实绑定（向下从严、向上宽松）

- 风险：低。
- 内容：声明低于 M 的每个信号（changeSurface/behaviorChange/topology/unitCount）必须绑定至少一条 current 仓库事实引用；声明 M/L 的宽松（升级不需证据，降级才需要）。一行校验逻辑，把谎报成本从 0 提到"必须登记能撑住声明的事实"。
- 前置：3.3（行为检测先于声明检测，可获越级频率数据）；可与 3.x 同批或独立。
- 验证：单测覆盖"XS 声明无事实 → 拒绝/升级"。

### 4.2 finalize 级别审计（非阻塞报告）

- 风险：零（只读报告）。
- 内容：finalize 对比实际变更面（文件数、跨组件、是否动 contract/共享文件）与声明级别，不一致时交付快照给一行显式警告。审计而非门禁——不增加阻塞，让瞒报事后可见。
- 前置：3.3（可选，独立性强）。
- 验证：构造"声明 XS 实际跨组件"的 fixture 断言报告输出。

## 阶段 5：结构收敛（中成本 interface 变更）

### 5.1 交互族收敛（9 → ≤5）

- 风险：中（interface 变更，技能/文档/测试联动）。
- 内容：decision-ratification 并入 grill；acceptance-confirmation 并入 verification 交互；workspace-ownership 收窄为懒触发（8-13 清单第 1 条已定方向）。目标：grill / approval / ownership / rollback / route-confirmation 五种，其余降为参数。
- 前置：0.1（当前轮候选 1 已把 13 kind 统一到 answer()，本项只是合并 kind，不重做 plumbing）。
- 验证：全量测试 + 真实任务交互次数对比。

### 5.2 工具面收敛（50 → ~30）

- 风险：中（工具名被 8 个 SKILL.md 引用）。
- 内容：review job 一族 6-7 个收敛为 `dev_flow_review_job { action: claim|submit|sample|release }`；rollback 三工具、实现单元三工具同理。每少一个工具 = 少一套 schema/校验/文档/测试/技能说明。
- 前置：5.1（先并 kind 再并工具，避免双重迁移）；当前轮候选 2/3 已满足报告自己定的"候选 2 落地后再评估"条件。
- 验证：8 个 SKILL.md 同步更新 + routes/interop 全绿。

## 阶段 6：高成本收敛与高风险升级

### 6.1 错误码族化（332 → ~35 族 + 参数化细节）

- 风险：高（一次性迁移，现有测试/技能/doctor 引用具体码）。
- 内容：`APPROVAL_EVENT_CONSUMED` / `APPROVAL_REPLY_MISMATCH`… 收敛为 `{ code: "APPROVAL_INVALID", params: { why: "event-consumed" } }`，信息量不减，枚举/测试/文档缩小一个量级。
- 前置：5.2（工具面稳定后再动错误码，避免两轮 interface 迁移叠加）。
- 验证：全量测试 + 迁移清单核对（grep 旧码零残留）。

### 6.2 provisional lazy lock（真·惰性，唯一的高风险状态机变更）

- 风险：**高**（动"lock 是唯一写 seam"核心不变量：write-gate、route-workflow、schema、task/grillme 技能、status 投影、错误路径）。
- 内容：`dev_flow_start` 后允许 provisional-XS 起步（写文件、跑验证），lock 推迟到第一次 governed write（write-gate 触发轻量分类）或模型主动调用；**provisional 只允许从 XS 起步且只允许向上**。
- 前置：3.2（quick lock）的数据证明"还不够懒"才做；且 2.1 基线数据 + 3.1/3.2 干预后数据齐备。
- 硬约束：先在 policy 层写 `provisionalXSLock` 纯函数 + 单测，验证与 `assertTopologyLevel`、`RECLASSIFICATION_DOWNGRADE_FORBIDDEN` 的交互，再动 write-gate。
- 验证：专项验证"越级防线未开洞"（provisional 期间出现 S+ 信号必须能强制先 lock）。

## 阶段 7：复盘与预算刷新（长期纪律，每版本例行）

- 内容：
  1. 每版本末跑 `surface-check` 并对比上一版基线（工具/错误码/模块数）；
  2. 复盘 ceremony budget 数据：XS/S 实际交互数与目标线的差距；
  3. 触发条件回顾：若"模型为了走完流程而走流程"（编造 audit 条目、无脑点确认）成为常态，优先做减法而非加校验。
- 前置：1.1、1.2（测量仪长期在线）。

## 关键纪律（贯穿全程）

1. **一次只改变一个变量**：每次行为干预独立成版、独立验证，数据才可归因；
2. **干预目标不提前修**：验证中发现的、属于计划干预范围的摩擦，登记 `.scratch/` 不修；
3. **provisional 是最后手段**：只有 quick lock + boundaryAudit 默认处置被数据证明不足时才动核心不变量；
4. **测量仪长期在线**：ceremony budget 与 surface-check 永不拆除，它们是"不膨胀"的看门狗。
