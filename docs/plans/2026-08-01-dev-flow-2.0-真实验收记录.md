## 验收范围

本记录使用发布 bundle 对应的 v2 Core、Hook 和 MCP 代码，在临时 Git 仓库中驱动真实状态机；它验证工作流行为，不冒充用户在 Claude/Codex UI 中手工点击。分类只使用调查得到的范围、拓扑、执行方式和风险事实，不使用业务关键词名单。

## 关键观察

- standard M、light L、standard L 均只呈现一个动态 `approval:<id>`，没有固定 gate 名称或第二条确认路线。
- standard M 和 standard L 的计划审查分别生成 2 个、3 个独立角色任务；审查结果完成后才进入实现。
- standard M/L 的 coverage、rollback projection 从《实施计划.md》的结构化 Trace delta 生成，不要求额外人工维护 `coverage-matrix` 或 `rollback-units` 文档。
- 每个场景均自动捕获实现入口与实现完成 checkpoint（2 个），正常受保护文件写入没有误拦；最终均生成 delivery snapshot。
- 修复循环保留失败记录：相同 failure signature 连续两次无进展后进入 `waiting-user`，不会静默丢弃失败或伪造成功。
- 这三条 Core smoke 没有产生非预期用户打断；动态 approval 是唯一预期确认。宿主交接测试在 `HOST_E2E=1` 下 Claude↔Codex 双向 2/2 通过。
