## 0. 实施原则

1. 每个行为变更先补聚焦测试，再修改源码。
2. `plugins/dev-flow/dist/` 只在里程碑发布收尾时通过 `npm run build` 更新。
3. 先建立纯策略与状态合同，再切 Host/Skills；Host 不得自行复制路线判断。
4. 2.0 是 Feature State/contract 硬切换，不实现 v1 migration 或兼容执行器。
5. 每个阶段保持源码测试不依赖 dist，并运行目标测试与 `npm run typecheck`。
6. 当前工作区已有 staged 第一轮修复；实施时按里程碑整理，避免覆盖或混淆用户改动。
7. 智能体不执行 commit、push、PR；每个里程碑只报告文件和验证结果，由用户审核提交。

## 1. 里程碑与依赖

```text
M0 1.10.0 稳定性基线
  ↓ 真机验证通过
M1 v2 纯合同与特征测试
  ↓
M2 Intake + Classification Facts + State v2
  ↓
M3 Stage Capability + Artifact 收敛
  ↓
M4 内嵌 Review + Decision/Approval
  ↓
M5 自动自适应 Checkpoint + Repair
  ↓
M6 阶段化 Hook + 自动恢复
  ↓
M7 删除 risk-minimal 与旧合同
  ↓
M8 全路线/跨宿主/真机验收与 2.0 发布
```

M0 必须独立完成和验证。M1-M7 可以在 2.0 开发分支内按纵向切片推进，但每个切片必须保持可测试；禁止通过长期运行时 feature flag 同时维护两套路线。

## 11. 风险、回滚与实施注意事项

### 11.1 最大技术风险

1. v2 State、Review、Trace、Checkpoint 同时变化导致大爆炸重构。
   - 缓解：按纯合同 → state → stage → review → checkpoint → host 纵向推进；每层先写 characterization tests。
2. 放松写前 fileScope 后偏航发现过晚。
   - 缓解：pre-unit baseline、actual diff、单元边界审计和 material drift 阻止下一单元。
3. 自动修复循环隐藏真实问题。
   - 缓解：failure signature、progress evidence、连续无进展阈值和绝对轮次上限。
4. 内嵌 review 变成同一模型自我盖章。
   - 缓解：不可变 basis、独立 role jobs、诚实 assurance、Core 强制 blocking finding closure。
5. 中文路径跨平台不一致。
   - 缓解：固定映射、NFC 归一化、macOS/Windows/interop tests。

### 11.2 版本回退

2.0 创建 schema v2 状态后，不支持直接降级到 1.10 继续该 feature。发布前要求：

- 1.10 doctor 确认无未完成 v1 feature。
- 用户在升级前自行备份需要保留的 `.dev-flow/` 测试状态。
- 若 2.0 需要回退，恢复 1.10 与升级前状态备份；不尝试让 1.10 读取 v2 feature。

### 11.3 不应提前实现的内容

- 生产部署/云操作审批或通用 JIT gate。
- 领域案例/关键词分类器。
- v1 自动迁移工具。
- 为兼容旧 route 而保留的永久 feature flag。
- 对模型具体命令、工具和内部推理方式的流程规则。

## 12. 完成定义

2.0 完成不是“新 contract 能跑通”，而是同时满足：

- 路线、风险与状态模型简化并可长期扩展。
- 严格能力转为阶段内自动义务，没有被静默删除。
- 正常模型行为获得足够自由，技术问题能自动恢复。
- 真实语义偏航、高风险与破坏性回撤仍有不可绕过的控制。
- 两轮真机反馈中的交互摩擦不再复现。
- 文档、Skills、Core、Host、MCP、tests 和 dist 对同一 v2 合同达成一致。
