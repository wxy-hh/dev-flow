## 0. 事实基线（Claude Code 2.1.234 API，官方文档实证 + T0 spike 实测）

2026-08-19 对官方文档实时抓取 + 本机验证（`claude --version` = 2.1.234）。来源：code.claude.com/docs/en/hooks、/hooks-guide、/plugins、/plugins-reference、/settings、/discover-plugins。

**已证实（降为确认项，不是未知项）**：

- `PreToolUse` 可 `deny` 拦截 Write/Edit/Bash，`permissionDecisionReason` **模型可见**（fail-visible 成立）；`allow`/`ask`/`defer` 可用；`updatedInput` 可整体替换工具入参。注意：prompt 里 `@` 引用的文件**不触发** PreToolUse。
- `SessionStart`（matcher: startup/resume/clear/compact/fork）可注入 `additionalContext`；文档明说要快。
- `UserPromptSubmit` 载荷含用户**原始 prompt 文本**；可注入 `additionalContext`；`block` 会擦除 prompt（慎用）；默认超时 30s。
- `SubagentStop` 载荷直接含 `last_assistant_message`（文档推荐，不必解析 transcript）；`decision:"block"+reason` 可令子代理继续。
- `PostToolUse` 载荷含 `tool_response` 与 `duration_ms`；`additionalContext` 下轮喂给模型；Bash 失败走 `PostToolUseFailure`。
- `Stop` 可 `block+reason` 强制继续，**连续 8 次后宿主强制结束回合**。
- 插件可携带 `hooks/hooks.json`、`.mcp.json`（MCP 工具名作用域 `mcp__plugin_<plugin>_<server>__<tool>`）、skills/commands/agents；`.claude-plugin/plugin.json` 仅 `name` 必填，**version 可选**。
- 本地开发：`--plugin-dir <path>` 会话级加载；`/reload-plugins` 热重载；`claude plugin validate` 校验；环境变量 `CLAUDE_PROJECT_DIR`、`CLAUDE_PLUGIN_ROOT` 注入 hook 进程。

**设计约束（新发现，违者返工）**：

- `async: true` 的 hook **决策字段无效**（decision/permissionDecision/continue 全失效）→ 一切拦截型 hook 必须同步且快。
- `suppressOutput` 字段已失效（接受但忽略）→ 禁用。
- hook 输出字符串上限 10,000 字符，超出转存文件。
- 插件 hooks 改动**无自动 watch**，需 `/reload-plugins` 或新会话。
- exit code：0=成功（JSON 生效）；2=阻塞（理由去向按事件而异）；其他非零=不阻塞但 transcript 显示 hook error notice（若 stdout 是合法 JSON 则只看 JSON）。
- 默认超时：command hook 600s；UserPromptSubmit 30s。PreToolUse 超时**不阻塞**工具调用（天然 fail-open）。

**spike 实测（2026-08-19 T0 已完成，出处 `docs/2026-08-19-spike-结论.md`；原"未证实"清单全部有结论，零回炉零回退）**：

- **transcript 在 PreToolUse 实测滞后**——消息生成 55ms 后 hook 触发仍读不到触发它的 assistant 消息（`payload.tool_use_id` 客观法实证），实时检测不可靠。
- **拦截/注入 JSON 一律 `hookSpecificOutput` 格式**（`hookEventName` + 事件字段）；顶层 `permissionDecision`/`additionalContext` 在 2.1.234 被静默忽略（`unrecognized keys`），deny 会 **fail-open**——spike 最大版本坑（官方网页文档滞后，仍展示顶层写法）；验收时用 `--debug-file` 核对无 `unrecognized keys` 日志。
- **hook 脚本必须 `.cjs`**（仓库 `package.json` 为 `"type":"module"`）；输出 JSON 必须 `fs.writeSync(1,…)` 同步写（`process.stdout.write` + `process.exit()` 会丢输出）。
- **SubagentStop 连续 block 上限实测 9 次**（静默放行、无警告；Stop 已知 8 次带警告）→ 把关循环按 **≤8** 设计。
- **shell-form hook 全进程 P95=26.4ms**（瓶颈纯 sh+node 冷启动，脚本内 P95≈2ms）→ 两级 hook 预案裁决为**非必需**。
- **写入路径全覆盖无致命盲区**：Bash 重定向全家桶（`>`/`>>`/`tee`/`sed -i`/`cp`/`mv`）、子代理内写入、NotebookEdit 全触发 PreToolUse/PostToolUse；`@` 引用读不触发。
- **改 hook 代码新会话 0 步生效**（`-p` 非交互实测；交互模式长期会话热加载未实证，见 §8）。

## 1. 第 0 步：spike 方案（出结论前不写正式代码）

解决的真实问题：方向合同根因 4"反馈环过长"的反面——**在错误假设上写正式代码才是最长的环**。怎么算解决：产出"每项能力 过/不过/回退"结论表，MVP 设计没有一处押在未实测假设上。

### 1.1 验证清单（三层）

**L1 文档确认项**（每项 ≤30 分钟最小脚本，必须覆盖 MVP 精确组合，防走过场）：

1. PreToolUse `deny` + reason 模型可见——Write/Edit/Bash 三种 matcher 组合各跑一遍；
2. **PreToolUse 触发时 transcript 是否已含触发它的那条 assistant 消息**——意图块存在性检测的技术前提，双模式裁决点（见 3.2）；
3. SessionStart `additionalContext` 注入（startup / resume 各一遍）；
4. UserPromptSubmit 拿到原文 + 注入 context；
5. SubagentStop `last_assistant_message` 可读；
6. `CLAUDE_PLUGIN_ROOT` 在插件 hooks.json 里真实生效。

**L2 文档未答项**（产出数字与约束清单，无"过不过"）：

1. SubagentStop 连续 block 上限（Stop 已知 8 次封顶）；
2. **写入路径全覆盖实测**：Bash 重定向写入、子代理内写入、NotebookEdit、`@` 引用——各自触发什么事件、能否被拦。致命问题只有一个：**是否存在"写入文件系统而不触发任何事件"的路径**；
3. 裸 node hook 的 P95 延迟初测（裁决第 2.1 节两级 hook 预案）；
4. `/reload-plugins` 实际摩擦步数；`claude plugin validate` 行为。

**L3 组合行为项**（最值钱；丢弃原型，适用 prototype 技能规则：无持久化、无测试、throwaway 标记）：

50 行内"假流程"端到端：SessionStart 注入（状态播报 + **真实意图块规则文本**，顺带验规则遵守）→ 模型写文件被 deny 带理由 → **模型读懂理由并改正** → 用户说"好了"被 UserPromptSubmit 识别。判据：模型一次 deny 后走向正确动作（验 fail-visible 的真实性，不是 API 存在性）。用 Claude Code 默认模型跑一次，证"机制上信息可达"；模型个体差异留给方向合同 8.1 基准阶段。判定方法：人工读 transcript，报告附摘录做证据。

### 1.2 产出与归档纪律

- 代码全部进 `spike/` 目录，文件头统一标 `SPIKE THROWAWAY`；过程正常提交（可复核）；**MVP 骨架禁止 import spike/——抄结论不抄代码**；MVP 第一批完成后整目录删除。
- 报告 `docs/2026-08-XX-spike-结论.md` 永久保留：每项 过/不过/回退 + L2 实测数字 + 精确字段名/载荷样例 + L3 transcript 摘录。**知识入库可复用，代码入库但冻结。**
- 驱动方式：`claude -p` 非交互 + `--plugin-dir` 加载 spike 壳，脚本化可重复跑。

### 1.3 失败决策规则（三级）

| 级别 | 适用项 | 动作 |
| --- | --- | --- |
| **回炉** | 仅 PreToolUse 拦写入+理由可达（deny 生效 ∧ 理由进模型可见通道，缺一即回炉） | 停 MVP，回方向合同修订第 3 章范式 |
| **回退** | SessionStart（→首轮 UserPromptSubmit 注入）；UserPromptSubmit（→done+恢复兜底两通道）；SubagentStop（→PostToolUse 匹配 Agent 工具） | 报告点名：哪个合同场景降级、降到什么程度 |
| **约束收紧** | 性能数字、reload 摩擦 | 不动能力清单，收紧实现预算与工程环 |

**回退累积闸**：回退项 ≥2 时，进 MVP 设计前必须回用户确认仪式预算是否仍可达——不许 spike 报告自宣布"预案不是失败"就往前走。

**时间盒**：一周，**结论产出制**——到点未验完的项按"回退"处理，spike 永不拖期。

## 2. 底座设计

### 2.1 语言与构建

解决的真实问题：hook 是每事件冷启动的进程，方向合同 8.3 把 P95 定为生死线；同时根因 1 的教训是结构失控（4 个巨型文件）。怎么算解决：spike L2 实测 P95 达标；入口壳行数预算不破。

- **TypeScript + esbuild 单文件 bundle + node 运行**（typescript/esbuild 已在 devDependencies，零新增依赖）。
- 类型是结构防线（状态模型、policy 规则、载荷解析），构建毫秒级不拖反馈环。
- 性能预案：**两级 hook 已裁决非必需**（spike 实测 shell-form 全进程 P95=26.4ms、脚本内 P95≈2ms，单级 node 已满足"事件延迟不拖反馈环"；预算紧张时优先 exec form——`args` 直接 spawn node 跳过 sh，省 ~4ms——加精确 matcher，见 §0）。
- node 存在性是**安装期前置条件**（doctor 检查 + fail-visible），不是运行期假设。
- 平台边界：第一批 macOS/Linux，Windows 明示不在范围。

### 2.2 仓库骨架与真机验证环

解决的真实问题：方向合同四行表之"验证反馈环过长"。怎么算解决：改完源码到真机验证 <1 分钟，不发版、不装包。

```
dev-flow/
├── src/                    # TS 源码（纯函数 policy + 薄入口壳）
├── plugins/dev-flow/
│   ├── .claude-plugin/plugin.json   # 只写 name，不写 version
│   ├── hooks/hooks.json
│   ├── .mcp.json                    # done 工具 + 只读查询
│   └── dist/                        # esbuild 产物，gitignore
├── sandbox/                # 固定验证仓：种子入库（敏感路径样本、假源码、git 仓），产物 gitignore
├── spike/                  # 第 0 步产出，throwaway
└── package.json            # 版本唯一来源
```

- **版本单源**：plugin.json 不设 version（文档证实可选）；分发产物的版本由构建脚本从 package.json 注入——消除历史 10+ 次版本同步事故的一类。
- **验证纪律：先 build 后验证**。验证入口脚本强制先构建（esbuild 毫秒级），不依赖"记得开 watch"——"验证了旧构建还当真"比发版更危险（误导是静默的）。watch 只是长会话迭代便利。
- 验证命令：`claude -p --plugin-dir plugins/dev-flow` 在 sandbox 起非交互会话跑场景脚本；sandbox 一键重置（`git clean` + 删 `.dev-flow/`）。
- marketplace 后置第三批；skills/commands/agents 不进第一批（评审 agents 第二批）。
- **MCP 工具面（第一批预算 = 2，封顶）**：`done`（唯一写工具，3.3）+ `status`（只读查询，T8）。宿主定形 `mcp__plugin_<plugin>_<server>__<tool>`——**server 名压最短（`df`），工具名即动作**，杜绝旧版三段重复的长名（旧名是自身命名失控，非宿主强制）。新增工具必答三问（4.3），不会长回几十个。精确渲染名 T8 时实证。

### 2.3 状态存储

解决的真实问题：方向合同 5.4（文件系统是唯一事实源）、4.6（治理自身不成为阻塞）。怎么算解决：状态损坏/并发/手贱改坏都不阻塞开发，且可重建。

三文件，**写权限分工消竞态，不上锁**：

| 文件 | 内容 | 写者 | 写原语 |
| --- | --- | --- | --- |
| `.dev-flow/state.json` | 活跃主线、挂起列表、需求条目、治理强度缓存、连败计数、完成宣称锁、最近验收、verify 声明 | 仅同步 hook | tmp+rename 原子替换 |
| `.dev-flow/events.jsonl` | 证据链原始记录（append-only） | 所有 hook | 同步 append（<1KB/行，微秒级） |
| `.dev-flow/.gitignore` | 内容 `*` | 首次运行自创建 | 自包含隔离，**不碰业务仓 .gitignore** |

- 读一律 **fail-open**：非法 JSON = 系统故障 → 警告+审计+空状态放行；重建只走 doctor 手动触发（先备份），**只报警不自修复**（方向合同 4.6）。
- 状态根 = `${CLAUDE_PROJECT_DIR}/.dev-flow/`：worktree 各有独立状态（与"一条 worktree 一条任务线"吻合）；子目录开会话不落错位置。
- **events 是事实源，state 是缓存**——崩溃导致两者不一致时以 events 重建 state，这是 doctor 重建的数据基础。
- events.jsonl 不轮转（年 MB 级），写进已知边界；finalize 归档是 4.3 加法候选。
- schema 字段级设计在 0.x 契约自由期内由实现定，additive-only 自律从第一天执行。

## 3. 机制设计（MVP 第一批）

### 3.1 事件→机制映射（5 个注册点，不多挂一个）

| 注册点 | 职责 | 同步性 |
| --- | --- | --- |
| `SessionStart` | 恢复播报（5.6）+ 意图块规则常驻注入（3.2）+ done 兜底检测（3.3）；**第一批不读 git status**（要快），git 静默对账第二批 | 同步 |
| `UserPromptSubmit` | ① 用户通道完成确认 ② 逃生门（"急，直接改"）③ 主线切换（"先弄那个"）④ 用户终裁解锁 | 同步 |
| `PreToolUse` matcher=`Write\|Edit\|MultiEdit` | 首写入门禁强制层 + 敏感路径硬门禁 + 行为信号采集 | 同步 |
| `PreToolUse` matcher=`Bash` | ① 拦不可逆操作（push/删表/发版，防线③）；② **启发式检出写入目标**（`>`、`>>`、`tee`、`sed -i`、`cp/mv` 目标路径）：命中敏感路径表 → 拦截/升级，并记入 `file.changed`（补证据链与自动 commit 的覆盖缺口）。代码内快路径：正则无命中立即 exit 0；解释器任意写入为明示残余风险（§8） | 同步 |
| `PostToolUse` | 证据链记账（文件改动、验收结果），append events.jsonl | **同步**（修正：append 微秒级，async 伤证据完整性且决策无效） |

### 3.2 首写入门禁（方向债前置的唯一落点）

解决的真实问题：方向合同 4.2——大任务最贵的错误是方向错误，纠错最便宜的moment是第一行代码写入前。怎么算解决：XS 任务瞬间通过零感知；需要对齐的任务在首写入瞬间被拦一次且只拦一次。

- **引导层**：模型首次写入前输出意图块，四要素——做什么 / 预计动哪些文件 / 敏感路径与风险标签 / **verify 命令（怎么算完）**。大任务扩展为按需求编号组织的计划摘要。
- **注入点（模型怎么知道要写意图块）**：双层——SessionStart `additionalContext` **常驻注入意图块规则**（≤5 行，与恢复播报同一 hook，零新增注册点；空状态也注入：规则是常驻约定，不是仪式）+ **deny 理由附模板兜底**（合同 6.1"报错附模板"，未注入或模型没遵守时的自救）。验证复用 L1-3（注入能力）与 L3（假流程直接用真实规则文本，验模型读到会遵守），不新增验证项。
- **强制层**：hook 硬校验意图块存在性 + 敏感路径声明。
- **检测主通道（spike L1-2 裁决，2026-08-19 落定）**："**一拦二放+审计**"（首写 deny 给模板，重试放行记 `intent.blocked`，finalize 审计显眼标注）。transcript 检测仅作**放行加分项**，且必须**限定 assistant 消息的 text 块**（防自注入污染：SessionStart 注入的规则文本本身含"#意图块"字样，全 transcript 搜索会永远命中）。**不把拦截押在实时 transcript 上**（实测滞后 55ms，见 §0）。
- 升级语义：写敏感路径且意图块已声明 → 放行+记账+治理升级；未声明 → deny（fail-visible：声明模板 + 用户一句话放行双出口）。

### 3.3 done 工具（完成宣称的唯一咽喉）

解决的真实问题：方向合同四行表之"反复确认走不完"——完成宣称必须一次到位且不可伪造。怎么算解决：验收未过 done 必驳回且理由说清缺什么；验收过了 done 必成功。

- **状态翻转永远只走 done 这一个咽喉**。用户通道只是触发器：UserPromptSubmit 识别完成语义 → 注入 additionalContext"请展示待完成摘要并向用户确认" → 用户确认 → 注入"请执行验收并调 done"。**hook 不直接翻转状态**（否则绕开验收硬前置）。误判成本=模型多问一句，提示级（4.6）。
- **兜底通道硬规格（T3 写死）**：SessionStart（startup/resume/clear/compact 全挂）检测四条件——存在未关闭主线 ∧ 有 `verify.passed` ∧ 其晚于最后写入 ∧ 无 `done.claimed`——**命中才注入**"主线 X 验收已过、只差确认完成，请向用户展示摘要并确认"；用户一句话确认 → done（走归并校验点）。**hook 永不自行完成宣称**（attestation 原则，合同 6.3：确认须宿主事件证明）。条件不命中（空状态/验收未过）→ 只注入恢复播报或什么都不注入——零仪式，兜底播报绝不变成空会话的仪式。
- **验收命令来源**：verify = 意图块第四要素（方向债前置）；PostToolUse 记账时按声明匹配 Bash 命令标记验收事件。声明演进：transcript 可靠时自动抓（事件追加，后者覆盖前者）；改命令场景靠"跑一次已声明的"或**用户一句话终裁**吸收，不自建改声明机制。
- **done 硬校验 = 时序双检查**：存在验收事件退出码 0 **且晚于最后一次写入事件**（代码变则验收失效，与评审"代码变结论失效"同源）。读 events 尾反向扫，微秒级。
- **验收事件记账区分退出原因（T6 实现要求）**：超时/被杀/非零退出码分开呈现——复用 `PostToolUseFailure` 事件与退出码分离（超时、挂死不得归一为普通失败），防"长测试挂死被当失败/通过误判"（坑 N-4，8-12-10b 同源）。
- **`verify: none` 须显式声明**（改文案类 XS）：声明进证据链、审计可见；缺省无声明 = done 驳回（fail-visible 给声明模板）。宽容的是内容，不是动作。
- done 不自己执行命令（MCP 超时+重复跑测试成本）。
- 第一批：驳回记 `done.rejected` 并连败计数+展示；**锁定动作在第二批**（方向合同 12 章分工）。
- 自欺残余风险（声明 `echo ok`）：防线在用户扫读、finalize 审计、第二批评审；合同 10.4 已承认蓄意绕过防不住，写入诚实账不加机制。

### 3.4 敏感路径表（宁窄勿宽）

解决的真实问题：方向合同 4.2 防线②——敏感路径是天然的升级信号。怎么算解决：四类客观路径触碰即拦截/升级；误报率近零（误报即新摩擦，10.2）。

初始集四类：

1. **密钥凭据**：`.env`、`*.pem`、`*.key`、`secrets/`、`.ssh/`、`.aws/`、`.npmrc`（豁免 `.env.example/.env.sample/.env.template`——它们就是要公开的）；
2. **CI 与发布**：`.github/workflows/`、`Dockerfile`、`deploy/`、`k8s/`、`*.tf`；
3. **数据**：`migrations/`、`schema.prisma`；
4. **元敏感（改门禁规则自身）**：`.dev-flow/`、`.claude/`、插件根——模型被拦烦了直接改 state.json/hooks.json 是新系统特有攻击面，零成本防线。

- 语义敏感（支付/鉴权逻辑）**不进路径表**（glob 误判率高）——走意图块自报 + 第二批评审角色派生。
- 项目补充：`.dev-flow/config.json` 的 `sensitivePaths` **只追加不覆盖**；配置文件整体可选，配置项数计入 4.3 复杂度预算（当前计数：`sensitivePaths`、`autoCommit`）。
- 匹配范围含 Bash 启发式检出的写入目标（§3.1）。
- **匹配实现（T4 要求）**：路径比较前做 **NFC 归一化 + symlink 目标解析**——macOS 文件系统常存分解（NFD）路径，归一化防漏判/误判；symlink 按目标解析后匹配（坑 N-5，旧测试 `v2-intake-handoff`/`symlink-checkpoint-rollback-v5` 同源）。
- 第一批已知边界：漏报兜底只有项目配置（finalize 审计启发式第二批）。

### 3.5 证据链（零操作）

解决的真实问题：方向合同 6.6——追溯从"模型手工登记的图"（修 4 次全是登记遗漏）降级为自动归集。怎么算解决：开发者零操作，每个改动事后能讲清来历。

- **第一批事件类型（12+1 预算封顶）**：`session.start`/`intent.declared`/`intent.blocked`/`write.allowed`/`write.blocked`/`file.changed`/`verify.passed`/`verify.failed`/`done.claimed`/`done.rejected`/`escape.used`/`unlock`/`mainline.switch`。新增必答三问。
- **记事实，不记内容（红线）**：记路径/工具名/退出码/时间戳/主线 id/命中规则名/用户原话（截断 500 字符）；**永不记文件内容**（`.env` 场景=安全事故）；命令输出只留尾部 ≤20 行。
- `file.changed` 的来源含 Bash 启发式检出的写入目标（§3.1），否则自动 commit（§3.6）会漏掉 Bash 写的文件。
- 全同步 append；每事件一行 JSONL。
- 渲染与交付对照表第二批；第一批只保证记录完整可查询。

### 3.6 自动 git commit（阶段检查点，done 时）

解决的真实问题：方向合同"rollback 让位 git"若没有检查点落点就是空话；大任务撤回成本无人兜底。怎么算解决：done 成功即产出原生 git 对象，撤销=原生 git 操作，零新机制。

- **选择性提交**：只 `git add` events 里 `file.changed` 记录的主线触碰文件清单，**绝不 `commit -am`**——用户自己的未提交改动一个都不卷进来（与 5.1 选择性失明对称）。
- message 固定前缀格式带主线标识（可过滤可 squash）。
- **失败 fail-open**：merge 冲突中、detached HEAD、空提交 → done 照成，警告+审计。
- push 永远人工门禁（防线③）；`.dev-flow/config.json` 的 `autoCommit` 可关（默认 true）。
- 中途检查点第二批再议。

### 3.7 其余用户通道机制（UserPromptSubmit 承载）

- **逃生门**（5.5）："急，直接改"→ 放行+记 `escape.used`，事后审计可见。信任但记账。
- **主线切换**（5.7）："先弄那个"→ 当前主线挂起（状态保留）、新主线激活；写入归活跃主线，归属歧义零仪式纠正。
- **用户终裁解锁**（4.6）：用户一句话解锁，给的上下文记 `unlock`（信息注入，改变后续计数语义）。第一批无锁定动作，此通道为完成宣称误判纠正服务。
- 识别纪律：开放式语义只做温和注入（模型多问一句）；状态翻转只信确认短语的精确匹配（被询问后的下一轮）——不误判、不擦除用户 prompt。

## 4. 测试与性能

- **纯函数纪律**：hook 判断逻辑全部写成纯函数（载荷+状态 → 决策），入口壳只做 stdin 解析+调用+写输出。**入口壳行数设预算**，超预算=结构异味，进坑清单。
- **单测**：policy 纯函数全覆盖；敏感路径匹配加性质测试（任意输入不崩溃、豁免永不被拦）+ **NFC 归一化与 symlink 目标解析**两条用例（N-5）；Bash 写入目标启发式加解析用例集（重定向/tee/sed -i/cp/mv/变量与引号边界）。
- **真机冒烟**：sandbox 场景脚本（`claude -p` 驱动）覆盖主路径+脏路径；进程壳行为以此为准。
- **性能**：P95 目标线 **≤30ms**（spike 实测 shell-form 全进程 P95=26.4ms 支撑，写入 §7 判据 4；参考旧版 <20ms 目标，进程冷启动现实下由 spike 数据放宽）；手段=只读缓存、代码内快路径（正则无命中立即 exit）、token 面收敛（响应不返回全量状态）。

## 5. 坑清单核对机制（防"修一轮再爆一轮"）
