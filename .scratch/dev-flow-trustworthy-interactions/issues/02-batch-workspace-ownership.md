# 02 — 批量确认并持续追踪工作区归属

**What to build:** 当工作区出现一个或多个无法归因的路径时，用户可以基于明确清单一次选择全部纳入、全部排除或逐个确认；任何已经观察但尚未归属的路径都会持续阻塞，而不是从后续对账中消失。

**Blocked by:** 01 — 以路线确认为首条统一可信交互

**Status:** implemented; ready-for-review

- [x] 对账结果分别表达路径是否已观察和是否已有归属结论，两者不再互相替代。
- [x] 多个未知路径被绑定为一个稳定清单，并提供“全部纳入当前任务”“全部排除并先处理”“逐个确认”三个正式选项。
- [x] 批量回答只作用于呈现时绑定的路径集合；集合发生变化后旧回答不能继续消费。
- [x] 逐个确认模式不会遗漏、重复询问或静默接纳任何路径。
- [x] 未归属路径经过 checkpoint、提交观察或重复 reconcile 后仍保持待决，直到用户作出归属决定。
- [x] 用户纳入的路径记录为 user-adopted；排除路径不会被自动 stash、reset 或删除。
- [x] revision 0 的首个 ownership 问题可以通过一次真实回答完成，不需要 repair feature 或事件重建。
- [x] 通过公开 MCP 工作流重放多文件“全部纳入”和 checkpoint 后仍未知归属的场景。
