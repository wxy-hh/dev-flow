# 02 — 文本凭证语义解析

**What to build:** 文本通道的根本修复——用户手输的回答不再要求与任何转述文本逐字相等：事件只证明"用户在展示后回答过"，回答内容按受控语义等价解析到选项。

**Blocked by:** 01（spec 父票据）。

**Status:** implemented; ready-for-review

- [x] 统一归一化（剥标点、括号、空白、大小写）应用于事件匹配与选项匹配两条路径（text-normalization.ts）。
- [x] 事件匹配从"逐字相等"改为语义兼容（归一化后相等或一方为另一方前缀；前缀否定永不兼容）。
- [x] 确认语义词（确认、同意、批准、可以、好的、行、没问题、LGTM、approved）在存在唯一确认/接受类选项时生效，对所有交互种类全局一致。
- [x] 无确认语义的文本（等等、再看看、不对）拒绝且不改变状态。
- [x] 恢复指令区分"hook 故障"与"回答未识别"两种病因；回答未识别时列出当前问题候选。
- [x] 回归：带后缀标签事件 + 精简/完整 userReply 均落账；短答确认；展示前、跨宿主、已消费、多候选负例保持拒绝。
- [x] 附加：approval/rollback/review-risk 门禁的逐字二次检查同步语义化。
