# 01 — 结构化凭证与语义解析：可信回答的根本修复

**What to build:** 解除"文本逐字相等"这一归属根因：宿主记录的表单选中（选中即信任）直接按所选选项落账，文本回答按受控语义等价解析，任何入口都只需用户回答一次；决定依据偏移时呈现变化并请求一致性确认，而非重问。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

---

## Problem Statement

用户在 Claude Code 中通过 AskUserQuestion 表单选中确认后，Dev Flow 工作流经常不认账，要求用户再手输一遍文本。真实案例（m-level-issue-8499）中用户连续确认三次：表单选中"确认路线（推荐）"与"确认这条路线（推荐）"均被拒绝，只有手输精确文本"确认这条路线"才锁定成功。

根因：宿主捕获的表单选中在 hook 层被降级为纯文本，归属时又要求 agent 转述的 userReply 与事件文本逐字相等（两套归一化还不一致）。任何标签漂移——agent 展示时加"（推荐）"后缀、用户回答含 UI 后缀、agent 精简转述——都会导致归属失败。该问题自 1.10 起反复修复（自然语言匹配、统一 dev_flow_answer 入口、可信交互合同、原生问答解析），每次只放宽局部匹配或修改恢复话术，从未解除"文本逐字相等"这一根因，因此换个入口即复发。

## Solution

- **选中即信任**：宿主记录的表单选中（AskUserQuestion 结构化记录、原生 MCP 表单 accepted response）本身就是可信回答，直接按所选选项落账，不经过 agent 转述验证。
- **文本凭证语义解析**：文本消息按受控语义等价解析到选项——标签归一化（剥标点、括号、空白、大小写）+ 确认语义词（确认、同意、批准、可以、好的、行、没问题、LGTM、approved）+ 登记短语；不再与任何转述文本逐字比较。
- **依据偏移提醒**：回答落账绑定决定依据；依据变化时呈现变化并请求一致性确认，而非让用户重答原决定。
- **安全约束保持**：展示之后、同宿主、唯一未消费、落账必须有宿主事件；否定/暂停语义文本拒绝。

## User Stories

1. 作为用户，我希望在表单中选中一次即完成确认，从而不再手输第二遍相同文本。
2. 作为用户，我希望选项标签带"（推荐）"等展示后缀时选中仍被识别，从而 UI 展示不影响归属。
3. 作为用户，我希望文本回复"确认这条路线（推荐）"与"确认这条路线"等价，从而不必与展示文本逐字一致。
4. 作为用户，我希望对当前唯一待决问题回复"可以、好的、行、没问题"即可确认，从而短答同样有效。
5. 作为用户，我希望"确认、同意、批准、approved、LGTM"在所有交互种类中一致生效，从而不必记每种问题的回答方式。
6. 作为用户，我希望"等等、再看看、不对、先这样"等无确认语义的文本不被当作确认，从而不会被误确认。
7. 作为用户，我希望确认过的决定在依据变化时收到"依据已变化"的提醒并只确认变化，从而不必重答原决定。
8. 作为用户，我希望智能体如何展示问题、如何转述我的回答都不影响我的回答被接受，从而不用为系统留证而重复操作。
9. 作为用户，我希望旧消息、其他宿主的消息、已消费的消息不能用于确认当前问题，从而回答来源保持可信。
10. 作为用户，我希望任何被拒绝的回答都不改变工作流状态，从而失败尝试不留痕、可安全重试。
11. 作为用户，我希望 hook 停摆导致的失败明确说明是 hook 问题而非回答方式问题，从而采取正确的恢复动作。
12. 作为用户，我希望升级后已在进行中的任务不中断，旧记录（无结构化字段）仍可完成归属，从而无需迁移数据。
13. 作为插件维护者，我希望所有七类交互（路线确认、执行批准、工作区归属、grill、风险接受、回滚确认、任务切换）共享同一语义解析，从而修复一次覆盖全部。
14. 作为插件维护者，我希望结构化凭证与文本凭证走同一归属判定入口，从而不出现两套行为。
15. 作为审计者，我希望每次落账都对应一个宿主事件，从而回答来源可审计、防智能体伪造。
16. 作为审计者，我希望确认记录绑定决定依据，依据变化后能看到明确的失效原因与一致性确认流程，从而审计语义真实。

## Implementation Decisions

- **凭证模型**：可信回答分两类凭证——结构化凭证（宿主记录直接携带所选选项）与文本凭证（宿主记录的用户原话）。智能体转述不构成凭证（ADR-0002）。
- **结构化凭证来源**：Claude AskUserQuestion 宿主记录（hook 事件中的问题、答案与选项结构对齐后记录所选选项）与原生 MCP 表单 accepted response。hook 记录回答事件时携带结构化字段，不再只落文本。
- **归属判定**：存在展示之后、同宿主、唯一未消费的结构化凭证时，直接按凭证所选选项落账；否则使用文本凭证做语义解析。userReply 与事件文本的逐字比较整体移除。
- **语义解析**：统一归一化规则（剥标点、括号、空白、折叠大小写）应用于全部匹配路径；确认语义词集与登记短语对所有交互种类生效；保留标签等价与唯一子串规则；无确认语义的文本（否定、暂停、无指向）拒绝且不改变状态。
- **依据偏移提醒**：回答落账绑定决定依据（哈希）；依据变化时呈现"依据已变化"并请求对变化本身的一致性确认，沿用现有 stale 校验语义并扩展至执行批准等交互；不再因阶段重进或无关变化重问。
- **兼容**：旧事件与旧交互记录（无结构化字段）按文本凭证路径处理，读时兼容，不迁移数据；5.0.3 进行中 feature 不受影响。
- **范围红线**：不引入自由自然语言理解；不降低防伪造约束（落账必须有宿主事件）。

## Testing Decisions

- **主 seam**：公开 MCP 工作流接口——以 mcpCall 驱动 dev_flow_answer / dev_flow_lock_classification 等工具，配合宿主事件注入。先例：mcp-answer-host-health.test.mjs、mcp-elicitation-v5.test.mjs、v5-dynamic-routes.test.mjs。
- **次 seam**：宿主 hook 协议——以 invokeHook 向 claude-hook 喂 PostToolUse(AskUserQuestion) 事件 JSON，断言结构化字段被正确记录。先例：trustworthy-audit-journeys.test.mjs、native-cross-host.test.mjs。
- **测试准则**：只断言外部行为（状态、错误码、审计事件、是否要求用户回答、能否推进路线），不测内部 helper。
- **正例**：表单选中一次落账；带后缀标签、精简文本、短答（可以/好的）确认；旧事件（无结构化字段）文本语义解析成功；所有交互种类共享语义。
- **负例**：展示之前的回答、跨宿主回答、已消费事件、多个候选事件、无确认语义文本（等等/再看看/不对）——拒绝且状态不变。
- **回归基线**：m-level-issue-8499 三次确认事件账本提炼为旅程——前两次（表单选中被拒）必须转正，第三次手输不再必要。

## Out of Scope

- 自由自然语言理解（"不引入模糊猜测"红线保留）。
- 路线分类、级别、风险标签、review 角色集合的修改。
- 历史事件数据迁移（读时兼容即可）。
- MCP 表单渲染与超时问题（既有处理不变）。
- Codex 侧原生问答（Codex 无 AskUserQuestion；文本通道自动受益，未来若引入原生表单再扩展）。
- 正常路线的阶段、工件、Trace、审查、验证义务的增减。
