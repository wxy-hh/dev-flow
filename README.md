# Dev Flow

Claude Code 插件：**宿主事件驱动的工作流治理**。流程状态在事件流上自动推进，门禁在事件边界自动拦截——写文件、跑命令、会话开始这些动作本来就会发生，模型不需要"记得走流程"，用户也不需要。设计原则叫**隐形治理**：小任务的理想体验是用户和模型都感觉不到流程存在，事后发现该拦的都拦住了、该记的都记下了。

第一批 MVP（T0~T9 验收闭环）提供四件核心机制：

- **首写入门禁**：第一次写文件前要求输出意图块（做什么/动哪些文件/风险标签/verify 命令），方向对齐发生在最便宜的纠错时刻；
- **完成宣称咽喉（done）**：只有验收通过才能宣称完成，验收未过必驳回且说明缺什么；
- **证据链**：每次会话、意图、写入、验收、完成宣称都自动记入事件流，零操作、可追溯；
- **敏感路径硬门禁**：四类内置敏感路径触碰即拦或升级，含 Bash 写入的启发式检出。

当前版本 `0.0.1`，处于契约冷冻点之前（0.x 契约自由演进）。

## 前置条件

- **Claude Code CLI**：实测版本 2.1.234（`claude --version` 查看）。插件依赖宿主事件（hooks/MCP），2.1.x 其余版本未逐一验证。
- **node >= 20**：安装期前置条件，hooks 以 node 运行（`node -v` 查看）。
- **macOS / Linux**：第一批不在 Windows 上验证。

## 在别的项目里装上去用起来

插件不是装包，是**目录加载**。三步：

```bash
# 1. 克隆本仓库（一次性）
git clone <本仓库地址> dev-flow

# 2. 安装依赖并构建（一次性）
cd dev-flow
npm install
npm run build        # esbuild 产出 plugins/dev-flow/dist/*.cjs（毫秒级）
```

`plugins/dev-flow/dist/` 是构建产物（已 gitignore，不随仓库分发）。**不构建插件不起作用**——hooks 通过 `${CLAUDE_PLUGIN_ROOT}/dist/*.cjs` 定位脚本，dist 不存在就没有任何行为。

```bash
# 3. 在目标项目里开会话，session 级加载插件
cd 你的项目
claude --plugin-dir /path/to/dev-flow/plugins/dev-flow
```

- 插件在**会话级**加载，只影响这次会话所在的项目，不写全局配置。
- 改插件代码（`npm run build` 之后）**新会话生效**；交互模式当前会话可用 `/reload-plugins` 热重载。
- 非交互模式（`claude -p`）如需调用 MCP 工具，加 `--allowedTools 'mcp__plugin_dev-flow_df__*'`。
- 可用 `claude plugin validate /path/to/dev-flow/plugins/dev-flow` 校验插件结构（spike 实测通过，警告仅为 version/description 缺失——符合设计，版本单源在 package.json）。

### 状态落在哪

流程状态写在**目标项目根目录**的 `.dev-flow/`（由宿主注入的 `CLAUDE_PROJECT_DIR` 决定，在项目任意子目录开会话都不会落错位置）：

| 文件 | 内容 | 说明 |
| --- | --- | --- |
| `state.json` | 活跃/挂起主线、需求条目、连败计数、最近验收等 | 缓存；只由同步 hook 写，原子替换 |
| `events.jsonl` | 证据链原始记录（append-only） | 事实源；state 可从它重建 |
| `.gitignore` | 内容 `*` | 首次运行自创建，自包含隔离，**不碰业务仓的 .gitignore** |
| `config.json` | 项目配置（可选） | `sensitivePaths`、`autoCommit`，见下文 |

`.dev-flow/` 自 gitignore 自己，不需要也不应该手动加进业务仓忽略列表。每条 worktree 有独立的 `CLAUDE_PROJECT_DIR`，所以状态也各自独立（一条 worktree 一条任务线）。

### 关于安装方式

目前**没有装包式安装**（marketplace 分发排在第三批）。只有本仓库目录加载这一种方式。

## 日常使用长什么样

以下按真实行为描述一个任务从开会话到完成的完整过程。

### 1. 开会话：听到恢复播报 + 意图块规则

每次会话开始，插件注入两样东西：

- **意图块规则**（常驻，每次会话都有）：提醒模型第一次写文件前先输出意图块。
- **恢复播报**（仅当有未关闭的主线）：形状是"你昨天在做「做标签功能」，做到写代码阶段，还差验证。"——恢复是插件的义务，不是你的记忆负担。如果上次"验收已过、只差确认完成"，会提示你确认收尾（这是 done 的兜底通道，见下）。

### 2. 首次写文件：输出意图块（四要素）

第一次写文件时，如果模型还没输出过意图块，写入会被拦一次，理由附四要素模板：

> 未检测到意图块。第一次写入前必须先输出意图块（以「#意图块」开头，2-3 行）：
> 做什么 / 预计动哪些文件 / 敏感路径与风险标签 / verify 命令（怎么算完成）。
> 输出意图块后重试本次写入即可。

意图块的格式约定（规则原文）：

> 第一次写文件前先输出意图块（以「#意图块」开头，2-3 行）：
> 做什么 / 预计动哪些文件 / 敏感路径与风险标签 / verify 命令（怎么算完成）。

示意（字段标签可用别名，见 `src/lib/transcript.ts`）：

```text
#意图块
做什么：给标签功能加颜色支持
预计动哪些文件：src/tags.ts、src/tags.test.ts
敏感路径与风险标签：无敏感路径
verify 命令：npm test
```

拦截是一次性的（"一拦二放"）：模型补上意图块重试即放行；模型在回复里已经写过意图块的直接放行。**XS 小任务零感知**——模型正常说话时就会带上意图块，不会卡流程。写敏感路径时例外：意图块里声明过该路径 → 放行并升级治理记账；未声明 → 拦（理由附声明模板，或你一句话放行，见"四个用户通道"）。

### 3. 写完后跑验收

意图块第四要素声明的命令就是验收命令。运行它（比如 `npm test`）：

- 退出码 0 → 记 `verify.passed`；
- 失败/超时/被杀 → 记 `verify.failed`，退出原因区分**超时 / 被杀 / 非零退出码 / 未知**，不归一为普通失败（长测试挂死不会被误当成失败或通过）；
- 带参数跑同一命令（`npm test -- --watch` 之类）也算匹配；改命令则不算，done 会要求重跑声明过的命令。

纯文案类改动没有验证命令的话，在意图块里**显式声明 `verify: none`** 即可免验收。缺省不声明 = done 必驳回（宽容的是内容，不是动作）。

### 4. 完成宣称（done）

验收通过后调用 done 工具：`mcp__plugin_dev-flow_df__done`（无入参）。

- **验收未过必驳回**，理由说清缺什么。典型驳回：
  - 无活跃主线 → "请先切换主线（如\"先弄那个 X\"）…"
  - 无验收声明 → 附声明模板；
  - 无验收通过记录 → "请先运行 verify 命令「…」且退出码为 0…"；
  - 最后一次写入晚于验收通过 → "验收已失效…请重新运行 verify 命令「…」后重试"。
- **验收过了必成功**：记 `done.claimed`、主线关闭、连败清零，然后**自动选择性提交**——只提交这条主线触碰过的文件（证据链里 `file.changed` 的清单），你手头未提交的改动一个都不卷进来。提交信息格式固定：

  ```
  chore(dev-flow): [<主线id>] <摘要>（自动提交 N 个文件）
  ```

  可用 `git log --grep='^chore(dev-flow): \['` 过滤。merge 冲突中 / detached HEAD / 空提交等场景下自动提交跳过，done 照常成功（fail-open），跳过原因写审计。

- done 还有两个触发通道：**用户确认**（对话里说"好了"，两跳确认后模型代调 done）和**恢复兜底**（下次开会话时检测到"验收已过、只差确认"主动提示）。三条通道任一触发即完成，状态翻转永远只走 done 这一个咽喉。

### 5. 随时查询：status

`mcp__plugin_dev-flow_df__status`（无入参，只读）：返回 ≤500 字符的紧凑摘要——活跃/挂起主线、连败计数、治理强度、最近验收、完成宣称状态、最近 10 条事件。状态损坏时返回"无状态"文本而不是报错。

## 四个用户通道

你的话是流程的一等输入。以下每类话术都会被识别并记账（识别纪律：状态翻转只信精确短语匹配，抱怨、疑问句如"怎么又不行""好了吗"不会被误判）：

### 完成确认（两跳）

- 第一跳，说"**好了**""**可以了**""**完成了**""**做完了**""**搞定了**""**完事了**""**收工**"等 → 模型被要求先展示待完成摘要、向你确认（防"这步完成了"被误判为全完成）；
- 第二跳（模型已展示摘要后），你确认"**确认**""**可以**""**好的**""**ok**"等 → 模型执行验收并调 done。

### 逃生门

说"**急，直接改**""**我授权**""**别拦了**""**直接放行**"等 → 放行并记 `escape.used`（含你的原话），事后审计可见。信任但记账，治理不挡该走的路。

### 主线切换

做到一半想换件事，说"**先弄那个登录 bug**""**先做标签功能**"等 → 当前主线挂起（状态保留），新主线激活，后续写入归新主线；切回同名主线自动重激活。同时只有一条主线接受治理，切换零仪式。

### 用户终裁解锁

对验收/拦截结果做终裁，说"**算过**""**通过吧**""**解锁**""**放行**""**我认可**"等 → 记 `unlock`（含你给的上下文），后续写入放行。它也是 done 误判的纠正通道。

话术说得模糊（"别走流程""换条线""差不多了""通融"）时不会写事件，只会让模型多问你一句确认——代价是提示级的，不会卡住。

## 敏感路径

### 内置四类（初始集，宁窄勿宽）

| 类 | 路径 | 规则名 |
| --- | --- | --- |
| 密钥凭据 | `.env`（豁免 `.env.example` / `.env.sample` / `.env.template`）、`*.pem`、`*.key`、`secrets/`、`.ssh/`、`.aws/`、`.npmrc` | `secret.*` |
| CI 与发布 | `.github/workflows/`、`Dockerfile`、`deploy/`、`k8s/`、`*.tf` | `ci.*` |
| 数据 | `migrations/`、`schema.prisma` | `data.*` |
| 元敏感（门禁规则自身） | `.dev-flow/`、`.claude/`、插件根 | `meta.*` |

写这些路径时：意图块已声明 → 放行 + 治理升级记账；未声明 → 拦，理由附声明模板 + "或用户一句话放行"。匹配前做 NFC 归一化和 symlink 目标解析（写一个指向 `.env` 的 symlink 也会命中）。**语义敏感**（支付/鉴权逻辑）不进路径表，靠意图块自报 + 用户扫读。

### 项目追加：`.dev-flow/config.json`

整体可选，只追加不覆盖（不写它就没有这个文件）：

```json
{
  "sensitivePaths": ["credentials.json", "internal/", "*.secret.yaml"],
  "autoCommit": false
}
```

- `sensitivePaths`：追加到内置四类之后。含 `/` 匹配路径段，含 `*` 做通配（`**` 跨层），否则按文件名精确匹配。损坏/畸形时按默认配置放行并写审计。
- `autoCommit`：done 时自动提交开关，默认 `true`；关掉后 done 照常成功、不产生提交。
- **push 永远人工门禁**：`git push`、`DROP TABLE/DATABASE`、`publish`（`--dry-run` 除外）、高危 `rm -rf` 会被拦，需你亲自执行或一句话授权。

## 故障与边界（如实说明）

- **状态损坏 fail-open**：`state.json` 非法 / `events.jsonl` 坏行时，hook 按空状态/干净事件放行，并在证据链里写一条 `audit.warning`，绝不阻塞开发（"门卫晕倒不该把楼锁了"）。**当前没有自动修复/重建工具**——"重建走 doctor"只是设计注记，doctor 尚未实现。`events.jsonl` 是事实源、`state.json` 是缓存，需要时可手工以 events 为准重建。
- **解释器任意写入是已知盲区**：`python -c "open(...)"` 这类解释器内写入无法从命令文本判出（属于蓄意绕过类，按设计承认防不住）；常见写入（`>` `>>` `tee` `sed -i` `cp` `mv`）都由 Bash 启发式检出并纳入证据链与自动提交。
- **模型行为仅在 Kimi 上实证**：意图块"模型读懂拦截并改正"只在 kimi-for-coding（K2.7）实测过，Anthropic 官方模型未验证——hooks 是宿主机制、与模型无关，风险低，但行为面有差异可能。
- **交互模式长期会话热加载未实证**：实测的是非交互（`claude -p`）新会话 0 步生效；交互模式长期会话中 hooks 改动的自动捡起未在本环境验证，必要时 `/reload-plugins` 兜底。
- **连败锁定、finalize 审计渲染、评审均在第二批**：第一批只计数展示连败，不做锁定。

## 性能

Bash 门禁快路径实测（100 样本，`build/bash-fastpath-p95.txt`）：**P95 = 17.9ms**，低于预算线 **≤30ms**（第一批验收判据之一）。快路径是代码内正则无命中立即退出的路径；spike 期 shell-form 全进程 P95 = 26.4ms（出处 `docs/2026-08-19-spike-结论.md`）。

## 开发与验证

```bash
npm run build        # TS 源码 → plugins/dev-flow/dist/*.cjs（先 build 后验证的纪律起点）
npm test             # 单测：node --test build/test/*.test.cjs（纯函数全覆盖）
npm run verify       # T1 真机冒烟：node/claude 检查 → build → 重置 sandbox → claude -p 端到端 → 断言
bash scripts/verify-t3.sh   # T3~T8 各是真机验证脚本（恢复播报/写门禁/用户通道/done/自动提交/status）
bash scripts/verify-t8.sh
npm run sandbox:reset # 一键重建 sandbox/work（seed 复制 + 独立 git init）
```

- **串行纪律**：所有 verify 脚本共用 `sandbox/work/` 验证仓，每个脚本开头都会重置它（`rm -rf` 重建）。**并行运行会互相清掉现场，必须串行**。
- 真机验证用 `claude -p` 起非交互会话跑场景脚本，需要本机 `claude` 可用且有可用的模型 provider。
- 版本单一来源是 `package.json`（构建时注入产物），`plugin.json` 不写版本。
